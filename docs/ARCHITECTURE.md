# Architecture

From 1.1.9, download messages carry exact bounded received/response Content-Length byte counts and elapsed transfer time. The panel derives decimal MB, average bytes per second, and remaining bytes divided by the measured rate. Warm-up under 250 ms, zero received bytes, or unknown total never produces a guessed ETA. Reopening queries counts plus elapsed time from the engine. A 500 ms window timer refreshes speed/ETA during visible downloads, including stalls, and is removed on phase completion or dismissal. The quick-action row becomes a transfer summary while downloading.

The persistent Go/Win32 engine owns the tray icon, taskbar materials and per-user settings. It waits for Windows messages. Version 1.1.2 opens an on-demand GDI+ panel and releases its process on dismissal. The older WebView2 path remains available for comparison with --css-preview/--css-check.

Taskbar materials use the ExplorerTAP COM interface with checked HRESULTs. CSS commands are posted asynchronously to the engine and acknowledged after completion; this avoids synchronous input COM-call failures. Allowed commands are explicitly listed in menu_css.go. The menu has no HTTP listener, remote page, external font, or arbitrary command bridge.

The native panel paints premultiplied ARGB into a reusable DIB and presents it with UpdateLayeredWindow/AC_SRC_ALPHA. Empty corners have zero alpha; the panel tint has 18% alpha. No redirected WebView or native accent backdrop sits behind the panel. It is live translucency, not a frozen desktop picture. Menu backdrop blur is not implemented; taskbar Glass/Acrylic effects remain unchanged. Native and WebView probes both produced opaque backgrounds under the previous host configuration, so the issue was not conclusively isolated to WebView2 alone.

One finite timeline animates the popup, blue selection plate and switch thumbs. A high-resolution ticker posts at most one outstanding frame up to 120 Hz and stops at the endpoint; timer resolution is restored afterward. Font and bitmap resources are reused while the panel is open. Outside-click and overflow-hide hooks exist only during the visible helper lifetime.

Foreground contrast adapts to bright/dark backgrounds with hysteresis. Four unobstructed corner pixels are sampled every 500 ms only while the panel is open; no desktop images are stored or transmitted. The helper exits after its close transition, so sampling and GDI+ resources do not remain in the idle engine. Keyboard Tab/Shift+Tab and Enter/Space are supported; native screen-reader integration is not yet implemented.

Mode and switch feedback is immediate. One engine command is in flight at a time; rapid input retains the latest intended state. Acknowledgements reconcile actual settings, and errors roll the controls back without a retry loop. Unchanged native host/border calls are skipped, with invalidation on theme/display/color changes and explicit refresh.

Preferences are stored in LOCALAPPDATA/Senja/settings.ini. Startup uses the current-user Run registry key. The update button starts Senja-Update.exe on demand; the idle engine does not import the HTTP client. The worker reads this repository's latest stable release API, rejects same/older versions, validates repository/tag-specific asset URLs and HTTPS redirect hosts, downloads within size/time limits, and verifies the EXE against SHA256SUMS.txt before staging it. From 1.1.13, the download worker saves a bounded pending record and exits without executing the installer. The old engine stays active. Ready state survives menu dismissal and app startup; automatic metadata checks do not overwrite it. Nanti only defers the prompt. Only a separate Mulai ulang Senja action invokes --apply-ready, which checks the staged path, regular file, newer version and SHA-256 again before executing it. Missing/changed staged files invalidate the pending record and return to a fresh download. Failed temporary downloads are removed. The installer performs the existing graceful engine replacement, retaining settings and enabled startup. From 1.1.7, a short-lived metadata-only worker runs 3 seconds after startup, every 6 hours after success, or after 30 minutes on failure. Cache and pending state survive menu dismissal. A Windows tray notification is submitted once per new version, respecting system notification settings; clicking it opens the panel. A red dot marks the install-only button; up-to-date and offline-without-known-update states are disabled. No executable is downloaded until the user clicks Perbarui. A second click during a check/download is ignored. Native menu progress is reported through bounded phase messages; from 1.1.8 the worker also reports received bytes (at most ten updates per second plus endpoints), using Content-Length for a real percentage or downloaded MB when unknown. The native bar interpolates for 160 ms on its existing finite animation ticker, retains progress across menu reopening, and stops at rest; the worker exits on completion. Release checksums protect transfer integrity, not against a compromised release account; releases remain unsigned.

Senja-Bar.exe embeds the portable ZIP, extracts it once into a version-and-content-addressed LOCALAPPDATA/Senja/app folder, starts the engine, and exits. Extraction checks paths and required files and publishes only a complete staging directory. An older running engine exits gracefully before replacement. An already enabled startup preference follows the new engine path. No administrator access or resident launcher is needed.

From 1.1.6, the new engine posts a one-time cleanup message after its tray and initial taskbar material have initialized successfully. A background worker validates the current managed install, then removes only older/equal-version inactive cache folders with matching version/hash names and complete .ready markers under LOCALAPPDATA/Senja/app. Newer versions, portable installs, unknown directories, the active folder, settings and personal Downloads are excluded. Root/target resolution and reparse-point checks precede recursive removal. Locked files are retried briefly; the .ready marker is retained until all other files are gone so a later startup can retry. Explorer and unrelated processes are never terminated. The download/installer cache under Senja/updates is separate and is not pruned by this cleanup.

Unmodified dependency hashes and source provenance are in DEPENDENCIES.json. The legacy cmd/samar path is internal only.

Taskbar tint adaptation reads SystemUsesLightTheme (the shell's theme, not the app theme) and samples nine points just outside each taskbar. Senja's popup is excluded; luminance extremes are trimmed. Background chroma subtly colors the theme tint, while Glass/Acrylic opacity adapts to support the shell's text contrast. Solid remains opaque and theme appropriate; Clear remains zero alpha. Native and XAML paths use the same palette. Foreground/move/minimize events and existing wallpaper/theme notifications request a debounced update; unchanged palettes skip material calls. No idle color polling, wallpaper decoding, screen images, or global theme changes are used. Sparse nearby samples approximate the underlying backdrop; they do not reconstruct content hidden behind an opaque taskbar.
