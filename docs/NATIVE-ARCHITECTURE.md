# Native engines and audio boundary

## Implemented
`internal/resources` owns resource eligibility, working-set trim and EcoQoS restoration through Windows APIs. `internal/systemtools/native_windows.go` owns memory/CPU samples, registry hardware identity, DXGI GPU enumeration, disk capacity, battery/power reads, native ICMP tests, DNS lookups, storage analysis and standard power-profile application. No PowerShell or third-party executable is launched for those functions.

`internal/mic` captures only when the user starts a test. PCM is processed in Senja's Go engine. With monitoring off, capture-only mode opens no output endpoint. With “Dengar suara sendiri” enabled, StartMonitor plays processed PCM through the explicitly selected local output at separately adjustable 0–100% monitor gain (70% default); no recording or upload occurs. Device and monitoring changes recreate the audio session cleanly inside the worker. Missing selected outputs fail explicitly instead of falling back to the system default. A physical headset may be preselected in the UI when output has not been chosen; monitoring remains off by default.

Seven presets tune input gain, gate, spectral noise reduction and bass character together while preserving device selection, enabled state and monitoring consent. Fokus dekat uses 100% DSP gain, −32dB gate, natural tone and 90% spectral reduction. The 32-bar ascending meter shows the processed peak on a −54 to 0 dBFS scale. Device icons are inferred from WinMM endpoint names, with generic/virtual fallbacks; they do not claim hardware form-factor detection.

The owned Go noise reducer uses a 512-sample FFT, 256-sample hop, sqrt-Hann overlap-add and a quiet-frame noise power estimator. The spectrum estimate freezes during louder speech and during structured quiet voice-band signals, so Wiener attenuation continues with the gate open. It adds 512 samples (10.7ms at 48kHz) of streaming delay; runtime is approximately 0.08ms per 20ms block on the tested machine, with zero per-block allocations in the synthetic benchmark. A deterministic mixed-tone/broadband-noise regression measured 12.69dB noise improvement and 0.998 target gain. These are synthetic results, not measured room speech quality. No voice enrollment, speaker identity, beamforming or simultaneous-talker separation is implemented; do not claim only the closest speaker is retained.

## Windows-owned operations
SFC, DISM, volume re-TRIM, Winsock and advanced DNS operations remain explicit Windows servicing tools. They are not a new repair algorithm authored by Senja. Existing taskbar helper DLLs and legacy optional web UI dependencies are outside this module replacement.

## Virtual microphone is not implemented
Applications select capture endpoints registered with the Windows audio stack. A local DSP function cannot manufacture such an endpoint. A standalone Senja audio device requires a separate Windows audio-driver project, a documented PCM transport, installation lifecycle, supported SDK/WDK build, signing, and real endpoint/latency testing. No driver binary or installation is claimed here. Do not weaken Secure Boot, driver signature enforcement, or Windows security to hide that missing capability.

The next implementation must bridge the Senja DSP output to an actual registered capture endpoint, verify FiveM/Discord receive the processed signal, and test device unplug, format change, worker crash, reboot and uninstall. Until then, keep global routing disabled and the local test clearly identified.

## Default neural voice processing
User approved embedded open-source noise suppression on 2026-10-29. Config defaults NeuralSuppression to true, including existing profiles without that field. RNNoise v0.2 runs locally in SenjaNoise.dll before the Go gate/EQ/limiter. The Go spectral reducer described above remains available only on the explicit non-neural path; it is not stacked on RNNoise. Missing or incompatible DLLs fail explicitly. The DLL is loaded by absolute executable-relative path, with an explicit test override.

SmartVoice (Auto / Deep otomatis) uses RNNoise speech probability for the gate, a 240ms hold and smooth release. Makeup gain is fixed at 1.3x, replacing the former syllable-driven upward gain. Deep adds bass EQ, without pitch shifting. This is speech suppression, not speaker enrollment or nearest-speaker isolation. NoiseReduction percentages configure the legacy reducer only; the neural path uses RNNoise's model directly.

The native shim accepts mono 48kHz PCM16, with 480-sample framing and 10ms bridge queueing in addition to model delay. Streaming chunk invariance, silent lifecycle, Windows-only runtime imports, typed-click synthetic attenuation and mixed TTS/click speech preservation pass. Active-signal native processing benchmark was about 0.32ms per 20ms block on the development machine. Real Rexus to Polaris monitoring starts and releases correctly; room speech/keyboard quality and remote application routing are not established by these tests. Source, license, build script and dependency hash are retained under native/rnnoise, scripts and docs.

## Startup and preview lifecycle
Each new test resets live monitoring to off in both UI and worker; opening a persisted profile cannot silently start headset playback. A user may explicitly re-enable preview during that session. Gain, suppression and Auto settings are applied before the audio thread starts, including on device changes. Output ramps in over 50ms. Wave input/output use a manual-reset driver completion event and drain completed headers, rather than polling a Go timer; capture/playback blocks are 480 samples (10ms). End-to-end latency still includes the neural model and device, so preview is not zero-latency monitoring or acoustic echo cancellation.

Event handling follows Microsoft's [waveform driver event callback guidance](https://learn.microsoft.com/en-us/windows/win32/multimedia/using-an-callback-to-process-driver-messages). Neural Auto uses a gentle 12% expander floor, 240ms hold and slower release to avoid hard cuts when speech probability becomes uncertain. It does not replace a real echo canceller with a playback reference.

## Current UI sample preview (supersedes live monitoring above)
Dengarkan contoh 3 detik sets PreviewSample explicitly. It captures after a 200ms warm-up into a bounded 144000-sample RAM buffer. waveInStop and waveInReset complete before previewStage=2 and before any waveOutWrite. Playback is one-shot, with a six-second output timeout and cancellable bounded waits; deferred clearing removes RAM PCM on return. The worker resets Enabled/Monitor/PreviewSample on completion and publishes phase/completion messages. The legacy StartMonitor API remains for low-level tests, but is not offered by the native UI. This breaks Senja's capture/playback feedback loop rather than pretending a denoiser is an echo canceller.

Sample output now uses one pinned contiguous three-second buffer instead of periodic 10ms refills. Shape/gain is applied once with fades only at the outer edges; waveOutWrite is called once and the wait loop only observes completion/cancellation. Driver reset/unprepare precedes unpin/PCM clearing. Capture has twelve 480-sample headers (120ms reserve). A completed local test is still not a registered Windows capture device.

Default output update: UI preview resolves output through WAVE_MAPPER (0xffffffff), so saved Output names are ignored. This is intentional per user instruction; it applies even if default is a speaker. Capture is stopped/reset before playback, and no system-default setting is changed. Manual input selection remains; opening its picker refreshes capture enumeration. Deep EQ has a subtle low-mid cut and restrained presence lift to preserve word clarity.

Explicit live self-monitor is now supported by a consumed LiveMonitorRequested startup flag plus Monitor runtime preference. It is off for ordinary tests and not a virtual capture endpoint. Live output is capped at 50%, uses eight 480-sample buffers and the default Windows output; acoustic echo cancellation is not implemented. Shared-meter mapping v2 adds a numeric message-kind field so live/sample phases no longer collapse to a generic status. Only numeric state/levels, never PCM, cross the mapping.

Current native Mic UI uses ToggleLive exclusively: ON requests capture/playback, OFF disables the worker. Hidden test/sample APIs are not reachable via page controls. Level telemetry is displayed on 50ms polls without continuous panel interpolation/animation; other control animations remain independent. This is a local listener, not a system microphone endpoint.
